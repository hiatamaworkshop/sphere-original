## 2. 同時接続数計算

### 2.1 Session TTL = 120s の場合

```
同時セッション = 新規接続レート × 平均セッション時間

例: 毎秒100人が接続
    100 conn/s × 120s = 12,000 同時接続
```

| 新規接続レート | 同時セッション | 規模 |
|---------------|---------------|------|
| 10 conn/s | 1,200 | 小規模 |
| 100 conn/s | 12,000 | 中規模MMO |
| 1,000 conn/s | 120,000 | 大規模MMO |
| 10,000 conn/s | 1,200,000 | ハイパースケール |

### 2.2 逆算: 100k同時接続を達成するには

```
必要接続レート = 100,000 / 120s = 833 conn/s
                                 = 50,000 conn/min
```

## 8. ボトルネック分析

### 8.1 現行設計の制約

| 制約 | 影響 | 緩和策 |
|-----|------|-------|
| 単一プロセスGateway | ~25k conn上限 | 水平スケール |
| インメモリRate Limit | ノード間共有不可 | Redis移行 |
| Session状態 | ステートフル | Redis Session |
| focus処理 | CPU集約的 | ワーカープール |

### 8.2 スケールアウト優先度

1. **Gateway水平分割** — 最優先
2. **Redis Session共有** — 必須
3. **Core分散処理** — 100k超で必要
4. **地理分散** — グローバル展開時

## 10. 結論

### 10.000 同時接続 (大規模MMO相当)

| 指標 | 値 |
|-----|-----|
| 新規接続レート | 833 conn/s |
| メッセージレート | 44k msg/s (ピーク110k) |
| メモリ要件 | 6-8 GB/Gateway |
| ネットワーク | 300-700 Mbps |
| ノード生成 | 30M/日 |
| ストレージ | 100 GB+ (代謝後) |
| サーバ台数 | 10-15台 |
| 月額コスト | $5,000-10,000 |

現行設計は**Phase 1（10k同時）まで**はそのまま対応可能。
Phase 2以降はRedis Session共有が必須。
