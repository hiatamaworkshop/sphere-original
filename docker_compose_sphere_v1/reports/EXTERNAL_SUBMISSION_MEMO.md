# External Submission Design Memo = contribution endpoint

Sphere Project - 外部情報提供の動線設計メモ

---

## 1. 概要

外部世界からSphereに情報を直接提供するルート。

---

## 2. 二つの提出経路

```
┌─────────────────────────────────────────────────────────────┐
│  経路 A: エージェント経由（標準）                            │
│                                                              │
│  外部世界 → Agent来訪 → 探索 → 評価 → Submit → Pipeline     │
│                         ↑                                    │
│                    検証・評価あり                            │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  経路 B: 外部直接提供                                        │
│                                                              │
│  外部世界 → /schema確認 → 整形 → Submit → Pipeline          │
│                                  ↑                           │
│                             検証なし                         │
└─────────────────────────────────────────────────────────────┘
```

---

## 3. 外部直接提供のフロー

```
[1. Schema Discovery - 形式確認]
    外部提供者 → GET /schema
    - このSphereが採用するデータ形式を取得
    - ExperienceCapsule, NodeSeed, NodeFlag の仕様確認

[2. Data Preparation - データ整形]
    外部提供者がSchemaに従ってデータを整形

    ┌─────────────────────────────────────────────────────────┐
    │  外部提供者が提供するもの（NodeSeed）                     │
    ├─────────────────────────────────────────────────────────┤
    │  ✅ tags: string[]     - キーワード → Tagger (16bit分類) │
    │  ✅ summary: string    - 内容要約 → Parser (座標決定)    │
    │  ✅ payload?: string   - 詳細内容                        │
    │  ✅ initialHeat: number - 初期熱量                       │
    │  ✅ flags: number      - ノードフラグ                    │
    ├─────────────────────────────────────────────────────────┤
    │  外部提供者が提供しないもの（/schema で明示）             │
    ├─────────────────────────────────────────────────────────┤
    │  ❌ vector       - null ("generated by Parser")          │
    │  ❌ evaluations  - [] ("do not write")                   │
    │  ❌ sourceNodeId - null ("external has no reference")    │
    └─────────────────────────────────────────────────────────┘

[3. Submission - 提出]
    外部提供者 → POST /sphere/contribute
    - ExperienceCapsule 形式で提出
    - evaluations: [] （空配列）

[4. Pipeline Processing - パイプライン処理]
    ┌─────────────────────────────────────────────────────────┐
    │  Gatekeeper → Parser → Tagger → Packer → Bookkeeper     │
    ├─────────────────────────────────────────────────────────┤
    │                                                         │
    │  1. Gatekeeper: 形式バリデーション                       │
    │     - schemaVersion チェック                            │
    │     - ノード数・サイズ制限                               │
    │                                                         │
    │  2. Parser: 座標決定（ParserBuffer 経由）                │
    │     - summary → ParserBuffer → 384次元ベクトル          │
    │     - topTier のみ（normal/ghost は空ベクトル）          │
    │     - バッチ処理効率化（遅延許容）                       │
    │                                                         │
    │  3. Tagger: 意味的分類（16bitTechnique）                 │
    │     - tags → 16bit flag                                 │
    │     - カテゴリ/属性の評価                                │
    │                                                         │
    │  4. Packer: SphereNode 構造化                           │
    │     - vector 付与（Parser から）                         │
    │     - flags 付与（Tagger から）                          │
    │     - metrics 設定                                       │
    │                                                         │
    │  5. Bookkeeper: DB保存                                  │
    │     - RefDB + ProjDB                                    │
    │                                                         │
    └─────────────────────────────────────────────────────────┘

[5. Incarnation - 受肉]
    ノードがSphereに配置される
    - 代謝の対象になる
    - エージェントが接近・評価可能に
```

---

## 4. 設計原則

### 4.1 形式準拠主義

```
✓ データ形式が体験カプセルに類似するSchemaに従っていればOK
✗ 過度な検閲は行わない
```

外部提供者を信頼しすぎず、かつ縛りすぎない。

### 4.2 Sphere固有のSchema

```
Sphere A: /schema → Format A（tags: max 140 bytes）
Sphere B: /schema → Format B（tags: max 280 bytes）
```

- 各Sphereが独自のデータ形式を採用可能
- 外部提供者はターゲットSphereの `/schema` を確認する義務がある
- 推奨しないが、Sphere間で形式が異なることは許容される

### 4.3 エージェントとの違い

| 特性 | エージェント経由 | 外部直接提供 |
|------|------------------|--------------|
| 検証 | 探索中に評価 | なし |
| 信頼性 | 高い | 不明 |
| 初期Heat | 探索結果に基づく | 提供者が指定 |
| 用途 | 知識の発見・評価 | 既知情報の投入 |

---

## 5. 注意点とリスク

### 5.1 検証の欠如

エージェントによる「知覚・評価」プロセスがない。
- 情報の信頼性が担保されない
- 悪意ある情報が直接入り込む可能性

### 5.2 対策

1. **Gatekeeperによる検閲**
   - 形式バリデーション
   - サイズ制限チェック
   - 禁止パターン検出

2. **代謝による淘汰**
   - 低品質な情報は自然に減衰
   - エージェントが評価しなければ消滅

3. **エージェントによる事後検証**
   - 外部提供情報もSphere内に存在すればエージェントが評価可能
   - 評価が低ければ減衰が加速

## 6. API

### 既存エンドポイントの使用

```typescript
// Schema確認
GET /schema
→ { ExperienceCapsule, NodeSeed, NodeFlag, example }

// 提出（エージェント経由と同一）
POST /sphere/contribution
← ExperienceCapsule
→ { success, nodeCount }
```

### 将来的な拡張（案）

```typescript
// 外部提供専用エンドポイント（オプション）
POST /sphere/contribute
← ExperienceCapsule + { source: string, metadata?: object }
→ { success, nodeCount, warning?: string }
```

外部提供を明示的に区別したい場合の拡張案。
現時点では同一エンドポイントで十分。

## 7. 実装状況

| 機能 | 状態 | 備考 |
|------|------|------|
| GET /schema | ✅ 実装済 | ExperienceCapsule 形式を公開 |
| POST /sphere/contribute | ✅ 実装済 | 外部提供専用エンドポイント |
| Pipeline 処理 | ✅ 実装済 | 下記参照 |

### Pipeline 詳細（設計確認 2026-02-01）

| ステップ | コンポーネント | 役割 | 備考 |
|----------|---------------|------|------|
| 1 | Gatekeeper | 形式検証 | schemaVersion + サイズ制限 |
| 2 | Parser | 座標決定 | summary → vector[384] |
| 3 | Tagger | 意味分類 | tags → 16bit flag |
| 4 | Packer | 構造化 | SphereNode 組み立て |
| 5 | Bookkeeper | DB保存 | RefDB + ProjDB |

### Parser と Tagger の役割分担（重要）

```
┌─────────────────────────────────────────────────────────────┐
│  Parser: 座標決定                                            │
├─────────────────────────────────────────────────────────────┤
│  入力: summary (内容要約)                                    │
│  出力: vector[384] = SphereNode の空間座標                  │
│  処理: Embedding Model (all-MiniLM-L6-v2)                   │
│  バッファ: ParserBuffer（受肉時は遅延許容）                  │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  Tagger: 意味的分類（16bitTechnique）                        │
├─────────────────────────────────────────────────────────────┤
│  入力: tags[] (キーワード配列)                               │
│  出力: 16bit flag = カテゴリ/属性フラグ                     │
│  処理: タグ評価ロジック（Embedding ではない）                │
│  例: ["clustering", "algorithm"] → 0x0042                   │
└─────────────────────────────────────────────────────────────┘

[修正済 2026-02-01]
  - IncarnationParser: summary → vector[384]
  - Tagger: tags → 16bit flags (16bitTechnique)
```

### パーサー使用タイミング

```
パーサーA（来訪時）: Agent 初期座標決定
  - 入力: EntryRequest.query
  - タイムアウト: 200ms idle / 2s max（応答性重視）
  - Agent が待機中

パーサーB（受肉時）: Node 座標決定
  - 入力: NodeSeed.summary
  - タイムアウト: 5s idle / 30s max（効率重視）
  - Agent 帰還済み、遅延許容
```

---

## 8. 哲学

> 外部情報の提供は、Sphereの主権を侵すものではない。
> 形式さえ従えば受け入れる。しかし、価値は代謝が決める。
> その情報が生き残るかどうかは、Sphere内の評価次第。
>
> これは「開かれた門」であり「無法地帯」ではない。
