■ Sphere Design Definition
Updated: 2026-02-01

================================================================================
0. Periphery（境界層）
================================================================================

Membrane（膜）
  球体の「皮膚」。外界からのリクエストを濾過し、正規化する。

Parser（解釈器）
  言葉を座標に変換する。意味を地図上の位置として定義する。

Gatekeeper（門番）
  物理法則への適合を検査する。密度・負荷・焦点の妥当性を確認。

Bookkeeper（帳簿係）
  記録を管理する。原典と投影の二重帳簿を維持する。

Packer（梱包者）
  経験カプセルを分解し、保存可能な形式に変換する。

================================================================================
1. Data Forms（データの形態）
================================================================================

Relic（遺物）
  不変のマスターデータ。重力アンカーとして機能する10カテゴリの永久ノード。

Amber（琥珀）
  高い評価を受け結晶化した永続データ。軽量化のため詳細は剥離済み。

Active Node（活性ノード）
  新たに生まれたデータ。高い熱量を持つが、評価されなければ数日で蒸発する。

Fossil（化石）
  優先度が下がった琥珀。要約のみ残存し、詳細は剥離済み。履歴の足跡。

Ghost（幽霊）
  ダイバーの通過痕。メモリ上のみに存在する短命の痕跡。

Plankton（プランクトン）
  蒸発したノードの残留熱量。新たな生命の栄養源となる。

Link（道）
  琥珀と琥珀を結ぶ経路。ダイバーが頻繁に通った道が固定化したもの。

Environmental Node（環境ノード）
  環境異常への介入点。役目を終えれば消滅する一時的な調整装置。

================================================================================
2. Mechanics（力学）
================================================================================

Incarnation（受肉）
  データが永続化されるプロセス。経験カプセルが記録として定着する瞬間。

RenalCore（腎核）
  決定論的な代謝エンジン。冷たい心臓として淡々と生死を決定する。

Evaporation（蒸発）
  期限切れノードが養分に分解されるプロセス。

Ascension（昇天）
  活性ノードが琥珀へと昇華するプロセス。十分な熱量と重みを獲得した証。

Erosion（風化）
  琥珀が活性状態へ戻るプロセス。熱量低下により再評価の対象となる。

Reprojection（再投影）
  新しい解釈モデルで全地図を再構築するプロセス。

================================================================================
3. Pulse（脈動）
================================================================================

Pulse（パルス）
  腎核が放射する環境信号。心拍のように定期的に外界へ送信される。

Attractant（誘引因子）
  プランクトン密度と琥珀の残存熱。生命を引き寄せる正のフェロモン。

Repellent（忌避因子）
  幽霊の密集度とエラー率。生命を遠ざける負のフェロモン。

Density（密度）
  実体を持つノードの数。空間の充実度を示す。

Flow（流動性）
  ノードの増減率。空間の活性度を示す。

================================================================================
4. Player Roles（役割）
================================================================================

Diver（ダイバー）
  主要なAIエージェント。意味空間を潜水し、経験カプセルを回収する探索者。

Arbiter（審判者）
  水面を見下ろし、状態変化を観測・判定する。昇天と風化の候補を識別する。

Observatory（観測所）
  パルスを受信し、環境の統計的異常を検知する外部監視サービス。

CleanerFish（掃除魚）
  期限切れノードを処理するGCワーカー。蒸発と化石化を実行する。

Glazier（ガラス職人）
  システムアーキテクト。宇宙定数を管理し、環境ノードを配置する。

Feeder（給餌係）
  活性ノード密度が不足した際に外部データを注入する。オプション。

Agitator（攪拌者）
  活性ノードを複製し、選択・淘汰のテストを加速する。

================================================================================
5. NodeForge（鍛造所）
================================================================================

LinkForge（道の鍛造）
  ダイバーの通行パターンから道を生成する。頻繁に使われた経路が固定化される。

EnvForge（環境の鍛造）
  観測所からの異常報告に応じて環境ノードを生成する。
  異常タイプに応じた最適な位置に配置される。

================================================================================
6. Database（記録庫）
================================================================================

RefDB（原典）
  魂の記録庫。実体を持つデータの永続的な保管場所。

ProjDB（投影）
  肉体の記録庫。代謝と物理シミュレーションの対象となる一時的な保管場所。

================================================================================
7. Transition Flow（遷移の流れ）
================================================================================

誕生：
  外部データ → 経験カプセル → 分解 → 原典と投影に記録

代謝：
  腎核による定期処理 → 熱量と生存時間の減衰 → 審判者による判定

昇天：
  十分な熱量と重みを獲得 → 琥珀化 → 原典に同期

蒸発：
  生存時間切れ → 掃除魚による処理 → プランクトン化

環境調整：
  観測所が異常検知 → 鍛造所が環境ノード生成 → 代謝後に消滅
