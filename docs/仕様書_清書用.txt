
2. 定常代謝アルゴリズム（Renal Core Logic）Renal Coreは、以下の数理モデルをバックグラウンドでループ実行する。恒常性維持（Dynamic TTL Decay）:$$TTL_{new} = TTL_{current} - (\alpha \times LoadFactor)$$※$LoadFactor$はメモリ/ノード数に比例。リソース逼迫時に忘却を加速させる。自動リンク発火（Spectral Linking）:2つの琥珀 $N_1, N_2$ 間の距離が近く、かつ共通の通行量 $T$ が閾値を超えた場合、関係性を示す LinkNode を生成する。

3. 境界処理パイプライン（Periphery Processing）Ingestion: 外部投稿またはAPI結果を受信。Vectorization: LLM Embedding APIにより座標計算。Transcoding: L1(Vector), L2(Summary), L3(Ref) への構造化。Injection: 空間への配置。帰還エージェントのカプセル（Experience Log）がある場合は、ボーナス $A$ 値を付与。

4. I/O インフラストラクチャInput: JSON POST（データ寄付、エージェント帰還）。Output: Stream/JSON（琥珀エクスポート、検索結果）。Pulse (UDP/WebSocket):JSON{ "heartbeat": 102, "active_nodes": 4500, "heat_map": [...] }
※可視化エンジンはこのパルスをサブスクライブして描画する。

5. パフォーマンス最適化Vector Search: HNSW インデックス（pgvector 等）を使用し、検索を $O(\log N)$ に抑える。Lazy Cleaner: クリーナーは全件スキャンせず、エージェントがアクセスした周辺セルから優先的にトリガーする。

1. ノード爆発への回答：階層的「折り畳み」構造
人物Aに膨大なエピソードがある場合、すべてのノードを同一平面に並べると検索負荷が跳ね上がります。
「重力源」による代表化: 人物Aという「重力源ノード」だけをマップに常駐させ、エピソード群は背後に「折り畳んで」隠します。
「Focus（知覚半径の拡大）」の制御: エージェントが「詳しく知りたい」と望んだときだけ、その座標周辺に一時的にノードを展開します。
クォータ制: 1エージェントが展開できる同時ノード数に上限を設ける。
TTL（自動消滅）: 観測されなくなったノードは、雪が溶けるように自動で折り畳まれ、メモリを解放する。
コストの意識: 展開は「エネルギー（計算資源）」を消費する行為とし、安易な全展開を防ぐ。

2. データの投入とラベリング：グラデーション評価
手動での全評価は不可能なため、投入時に「タグの義務化」と「自動階層化」を行います。
上位タグと下位タグ: 「名前・場所・年代・認知度」といった基本属性を上位タグとし、そこからエピソード（下位）へと繋がる親子関係を定義します。
座標の自動付与: CSV等のプレーンデータは、投入時にパーサーが座標（意味の場所）を計算します。評価（フェロモン）はゼロですが、「場所」が決まることで、エージェントによる発見が可能になります。

3. システム基盤：mmap と分散パーサーの分業
なぜ同時接続に耐えられるのか、その物理的な裏付けです。
スフィアマップ（インメモリ）: パーサーは起動時に「地図（IDと座標）」のみをRAMにロードします。これは軽量です。
原典DB（mmap）: 詳細データはSSD上に置き、mmapを用いて「必要な時だけメモリに見せる」遅延ロードを行います。OSが物理レイヤーで高速化するため、DBアクセスより遥かに速い。
パーサーの負荷分散: エージェント数が増えたらパーサー（プロセス）を増やし、それぞれが「地図」を参照しながら数十人ずつのエージェントのナビゲートを担当します。

4. マージとバッファ：知の代謝サイクル
「化石（不変の原典）」と「琥珀（価値ある知恵）」を抽出するプロセスです。
クリーン・マージ: フォークで評価の高かった「原典ID」のみを拾い、座標を最新モデルで再計算して新世界（聖域）を創生します。
バッファ期（幼生期）: 新世界誕生直後は「減衰」を緩め、新しいノードが定着しやすくします。これにより、マージ直後の「空っぽ」な感覚を防ぎます。

あなたの思想を反映させた、システム運用上の黄金律です。
