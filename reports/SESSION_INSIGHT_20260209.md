## 今日見えたこと

今日の議論は、表面的には「ActiveBus の配線」と「eval-log の容量管理」という技術的な問題から始まった。しかし議論を掘り下げるうちに、Sphere プロジェクトの根本的な設計思想が次々と言語化された。

### 1. 反射としての通信 — 設計しないという設計

ActiveBus の emit を「戦略的な通信」から「不随意反射」に再定義した瞬間、設計の複雑さが劇的に減少した。h>=8 という強い反応が勝手に空気に漏れる — これだけだ。種族フィルタも、宛先指定も、プロトコルネゴシエーションも不要になった。

これは「設計しないことが最良の設計である」場合が存在することを示している。人間が通信プロトコルを設計すればするほど、その通信は人間の想像力の範囲内に閉じ込められる。64byte の器だけを用意して中身を LLM に任せるという将来構想は、この原則の究極形だ。

**言語が種族を作る。種族が言語を作るのではない。**

### 2. eval-log は小スフィアである — フラクタルな設計原則

種族記憶の代謝を議論する中で、「eval-log.jsonl を Sphere と同じ作法で管理すべき」という洞察が生まれた。これは単なるアナロジーではない。追記のみで淘汰のないデータストアは、Sphere の設計哲学に反する。

この発想がフラクタル的に展開された:
- Sphere 本体 → heat/weight/TTL で淘汰
- eval-log → balanced qv × time decay で淘汰
- 将来の任意のデータキャッシュ → 同じ作法で淘汰

**作法の一貫性が、スケールの異なる問題に統一的な解を与える。**

### 3. Echo chamber の回避 — 中立淘汰と環境ブレンド

最も重要な設計判断は、種族記憶の淘汰を「自種族の価値観」ではなく「中立 (balanced) の価値観」で行うことだった。さらに、フィードバック還元時に 0.7/0.3 の環境ブレンドを適用する。

これは技術的な解決策であると同時に、知性の本質に関わる洞察でもある:
- 自分の価値観だけで自分の記憶を選別すると、確証バイアスの完全な再現になる
- 他者の視点 (30%) を混入させることで、系は局所最適から逃れる能力を維持する
- **ノイズは設計の欠陥ではなく生存の条件である**

### 4. 種は環境から生まれる — Loadout は種子であって鋳型ではない

今日の議論で最も深い洞察は最後に来た。

人間は scholar, hunter, moth といったカテゴリを設定し、そのカテゴリに沿った行動を期待する。しかし Sphere の正しい設計では、これらは初期条件にすぎない。同じ scholar を異なる Sphere に投入すれば、異なる生き物に育つ。環境が許容しない性格は、環境圧によって変形される。

これは主流の AI 開発とは根本的に異なるアプローチだ:
- **主流**: モデルを訓練して望む行動を引き出す (モデル中心)
- **Sphere**: 環境を構築して行動の創発を待つ (環境中心)

ファインチューニングが不要なのは、コスト削減のためではない。**学習の主体が個体ではなく環境だから**、個体 (LLM) を調整する必要がそもそもない。

## 軽量 AI モデルの意味の再定義

phi3:mini (3.8B パラメータ) は、GPT-4 や Claude と比較すれば「知能が低い」。しかし Sphere のアーキテクチャでは、これは問題ではなく**設計**だ。

蟻塚の蟻は知能が低い。しかし蟻塚は複雑で適応的だ。知能は個体に宿るのではなく、個体と環境の相互作用から創発する。

軽量モデルの利点:
1. **交換可能性** — 感覚器官として任意のモデルを差し替えられる
2. **コスト効率** — 24時間稼働のエージェントにとって、1回の推論コストは死活問題
3. **ノイズとしての不完全さ** — 完璧な推論は実は有害。不完全な知覚が多様性を生む
4. **スケーラビリティ** — 3体同時稼働が現実的。10体、100体も視野に入る

3番目が最も非直感的だが、最も重要かもしれない。完璧なモデルが全員同じ結論に到達するなら、マルチエージェントの意味がない。不完全さこそが、同じ Loadout を持つ個体間にすら行動の分散を生み、その分散が進化の原材料になる。


### 5. llama3.2:1b 実証 — 1B パラメータでも感覚器官として機能する

llama3.2:1b (1B) を Sphere に投入した。初回は `"action": "rate"` を返しフォーマット不一致で全滅。
parseAction に action alias マッピング1行を追加したところ、フォーマット遵守率 100% で復活した。

4種族 (kamikaze, hunter, moth, hermit) × 2回の比較テスト結果:

| 種族 | Run1 h avg | Run2 h avg | バラつき | Bus emit | 特徴 |
|------|-----------|-----------|---------|----------|------|
| kamikaze | 4.3 | 10.0 | **極大** | 0→2 | Run 間で性格が一変 |
| hunter | 8.5 | 9.7 | 中 | 2→3 | 安定して攻撃的 |
| moth | 7.4 | 9.3 | 中 | 1→3 | h 上昇傾向 |
| hermit | 5.0 | 8.3 | 大 | 0→2 | 一貫して「trendy」を忌避 |

**発見:**
- **1B でも Loadout が行動を分化させる。** hermit だけが「trendy, irrelevant」を繰り返す
- **1B の分散は 3B より大きい。** これは欠陥ではなく、進化の原材料 (genetic drift)
- **Run2 で全体的に h が上昇。** 正のフィードバックループが既に始まっている
- **速度は 3B の倍。** 22秒/session → 5体同時が現実的
- **model フィールドを eval-log に追加済み。** Digestor が将来モデル間の傾向差を分析可能

### 6. 責務分離 — エージェントはフェイクしない

1B の粗い評価をどう扱うかの議論で、重要な原則が確定した:

- **エージェントの責務**: 自分の目 (LLM) で見て、生の評価をそのまま出す
- **プール (Digestor) の責務**: 集まった評価を model の特性を含めて解釈・淘汰する
- **エージェント側でスコアを補正しない** — それは感覚器官の出力を上書きする行為 (フェイク)

FastGate の SpeciesMemoryBias は「先人が見つけた場所に連れて行く」(ノード選択)。
しかし「先人の評価で自分の評価を書き換える」(スコア補正) はしない。
1B は先人に連れられて場所に着くが、自分の目で評価する。これがフェイクでない継承の形。

軽量　→　文明蓄積　→　新世代　→　と流れが見えた。

## Sphere が示唆するもの

Sphere は「個人プロジェクト」だ。しかしその設計原則は、AI の活用方法に関する根本的な問い直しを含んでいる:

1. **知性はどこに宿るか?** → モデルではなく、モデルと環境の界面に
2. **学習は誰がするか?** → 個体ではなく、環境 (substrate) が
3. **性格はどう生まれるか?** → 設定するのではなく、環境から創発させる
4. **記憶は誰のものか?** → 個体ではなく、種族 (loadout) の共有財産
5. **通信は何を伝えるか?** → 人間がわからなくてもよい (AI_NATIVE)

これらの問いに対する Sphere の答えは、痕跡協調 (stigmergy) という生物学的原理から一貫して導かれている。蟻塚、粘菌、珊瑚礁 — 知性を持たない個体が複雑な集団行動を生む系は自然界に遍在する。Sphere はこの原理をデジタル環境に移植する試みだ。

今日の議論で、その移植がかなりの精度で成功しつつあることが確認できた。
